# 全链路UTC时区配置指南

## 概述

本文档详细说明了如何配置Django和MySQL以使用UTC时区，并提供前端处理时区的最佳实践。

## 为什么选择UTC作为标准时区？

使用UTC作为系统内部时区有以下优势：

1. **数据一致性**：所有时间戳都存储在同一时区，避免了时区混乱
2. **避免夏令时问题**：UTC不受夏令时调整的影响
3. **国际化支持**：适用于全球用户的应用程序
4. **简化服务器迁移**：服务器位置变更不会影响时间数据
5. **行业标准**：符合大多数国际化应用的最佳实践

## 配置步骤

### 1. Django配置

在`settings.py`中设置：

```python
TIME_ZONE = 'UTC'
USE_TZ = True
```

这将使Django内部使用UTC时区，并启用时区支持。

### 2. MySQL配置

#### 临时设置（重启后失效）

```sql
SET GLOBAL time_zone = '+00:00';
```

#### 永久设置

**Windows**:
1. 找到my.ini文件（通常在MySQL安装目录或C:\ProgramData\MySQL\MySQL Server X.Y\）
2. 在[mysqld]部分添加：
   ```
   default-time-zone = '+00:00'
   ```
3. 重启MySQL服务

**Linux/Unix**:
1. 编辑my.cnf文件（通常在/etc/mysql/my.cnf或/etc/my.cnf）
2. 在[mysqld]部分添加：
   ```
   default-time-zone = '+00:00'
   ```
3. 重启MySQL服务：`sudo systemctl restart mysql`

### 3. 安装MySQL时区表

时区表对于使用命名时区（如'Asia/Shanghai'）进行转换是必需的。

**Linux/Unix**:
```
mysql_tzinfo_to_sql /usr/share/zoneinfo | mysql -u root -p mysql
```

**Windows**:
运行我们提供的`install_mysql_timezone_tables_windows.py`脚本。

## 前端处理时区

### JavaScript处理UTC时间

#### 显示UTC时间为本地时间

```javascript
// 从API获取的UTC时间字符串
const utcTimeString = "2025-07-03T10:00:00Z";

// 转换为本地时间显示
const utcDate = new Date(utcTimeString);
const localTimeString = utcDate.toLocaleString();

console.log(`UTC时间: ${utcTimeString}`);
console.log(`本地时间: ${localTimeString}`);
```

#### 提交本地时间为UTC

```javascript
// 获取用户输入的本地时间
const localDate = new Date(localDateString);

// 转换为UTC时间字符串提交给后端
const utcTimeString = localDate.toISOString();

// 发送到API
fetch('/api/endpoint', {
  method: 'POST',
  body: JSON.stringify({ timestamp: utcTimeString }),
  headers: { 'Content-Type': 'application/json' }
});
```

### 使用Moment.js（如果项目中使用）

```javascript
// 显示UTC时间为本地时间
const localTime = moment.utc(utcTimeString).local().format('YYYY-MM-DD HH:mm:ss');

// 提交本地时间为UTC
const utcTime = moment(localTimeString).utc().format();
```

### 使用Day.js（轻量级替代）

```javascript
// 显示UTC时间为本地时间
const localTime = dayjs(utcTimeString).local().format('YYYY-MM-DD HH:mm:ss');

// 提交本地时间为UTC
const utcTime = dayjs(localTimeString).utc().format();
```

### React组件示例

```jsx
import React, { useState, useEffect } from 'react';

const TimeDisplay = ({ utcTimeString }) => {
  const [localTime, setLocalTime] = useState('');
  
  useEffect(() => {
    if (utcTimeString) {
      const date = new Date(utcTimeString);
      setLocalTime(date.toLocaleString());
    }
  }, [utcTimeString]);
  
  return (
    <div>
      <p>UTC时间: {utcTimeString}</p>
      <p>本地时间: {localTime}</p>
    </div>
  );
};

export default TimeDisplay;
```

## 常见问题

### 时区转换失败

如果遇到错误：`Database returned an invalid datetime value. Are time zone definitions for your database installed?`

1. 确保MySQL时区表已安装
2. 验证MySQL全局时区设置为UTC
3. 检查Django设置中TIME_ZONE和USE_TZ配置

### Admin界面日期过滤器问题

如果Django Admin中的date_hierarchy过滤器出现问题，可以：

1. 移除CustomerAdmin类中的date_hierarchy设置
2. 或确保MySQL时区表正确安装

## 结论

通过以上配置，您的系统将实现全链路UTC时区标准化：

- 数据库存储UTC时间
- Django内部处理UTC时间
- 前端负责将UTC时间转换为用户本地时区显示
- 前端提交数据时将本地时间转换回UTC

这种方法确保了时间数据的一致性和准确性，无论用户或服务器位于哪个时区。
