# we_rss 文档索引

这组文档面向 `we_rss` 的前端开发、联调和排期协作。本文档集已按当前
仓库中的真实实现重新整理，重点补齐了最新数据结构变化，尤其是
`we_rss` 下全部模型已经对齐 `BaseModel` 这一点。

你在阅读这组文档时，要先记住一个总原则：`we_rss` 现在的数据库模型字段
比接口返回字段更多。也就是说，模型里已经统一具备 `tenant`、
`created_at`、`updated_at`、`is_deleted` 等字段，但前端实际能收到的
JSON 字段仍然以 serializer 为准，不能直接把模型字段当成 API 字段使用。

## 本次更新重点

这次文档更新主要覆盖了下面几类变化：

- `WechatCredential`、`WechatCredentialLoginSession`、`WechatFeed`、
  `WechatArticle`、`WechatSyncTask` 全部继承了 `BaseModel`。
- `WechatArticle` 现在使用官方字段名 `article_type` 表示文章类型，取值为
  `news` 或 `newspic`，不再使用泛化的 `type` 命名。
- 所有 `DELETE` 接口现在都应理解为软删除语义。数据会被标记
  `is_deleted = true`，随后从默认查询结果中消失。
- 所有 `we_rss` 数据都是 tenant 级共享数据，不是 member 私有数据。
- 异步任务返回结构已经按真实代码重新梳理，尤其是
  `result_payload` 会随 `task_type` 变化，前端不能写死单一结构。
- RSS 和正文输出接口虽然是 XML / HTML，但仍然要求成员鉴权和
  `X-Tenant-ID`。

## 推荐阅读顺序

如果你是第一次接这套能力，建议按下面的顺序阅读。

1. 先看 [00_总览与对接说明.md](./00_总览与对接说明.md)。
2. 再看 [01_凭证与扫码登录API.md](./01_凭证与扫码登录API.md)，先把登录态跑通。
3. 再看 [02_公众号API.md](./02_公众号API.md) 和
   [04_同步任务API.md](./04_同步任务API.md)，把公众号和任务链路接起来。
4. 再看 [03_公众号文章API.md](./03_公众号文章API.md)，把文章列表和详情跑通。
5. 最后看 [05_RSS与正文输出API.md](./05_RSS与正文输出API.md)，做阅读器或调试页。

## 最小可用链路

如果你只关心“现在前端最少要接到什么程度”，那就按下面这条链路实现：

1. 成员登录后，所有请求自动带 `Authorization` 和 `X-Tenant-ID`。
2. 创建扫码登录会话，轮询到 `credential_id`。
3. 设置默认凭证。
4. 搜索公众号并保存。
5. 触发公众号同步，并轮询同步任务。
6. 在文章列表里看到同步下来的文章。
7. 支持文章详情、已读、收藏、刷新。
8. 需要时读取 RSS XML 或正文 HTML。
