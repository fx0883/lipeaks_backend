# we_rss 前端开发排期版

这份文档面向前端负责人和排期协同者，目标不是重复解释所有接口细节，而是把
当前 `we_rss` 的真实能力拆成可执行的阶段和验收口径。

## 本期目标

这期前端工作的最低目标不是还原旧项目全部页面，而是跑通下面这条主链路：

1. member 带 `Member JWT` 和 `X-Tenant-ID` 正常请求 `we_rss`。
2. 完成扫码登录，拿到有效微信凭证。
3. 设置默认凭证。
4. 搜索公众号并订阅。
5. 触发公众号同步并轮询任务。
6. 在文章列表中看到同步下来的文章。
7. 支持文章标题搜索、收藏、详情和刷新。
8. 需要时读取 RSS XML 和正文 HTML。

只要这条主链路完成，本期前端就已经可交付。

## 排期前必须统一的共识

排期前建议团队先统一下面几条共识：

- `we_rss` 主数据是 tenant 共享，不是 member 私有。
- member 维度状态只有两类：`is_subscribed` 和 `is_favorite`。
- 当前没有 `is_read`，也没有 `PUT /articles/{id}/read/`。
- 公众号列表支持 `subscribed_only` 过滤。
- 文章列表支持 `article_type`、`search`、`favorite_only` 过滤。
- 文章搜索只搜 `title`。
- RSS / HTML 接口不是公开匿名地址。
- `result_payload` 是动态结构，不能写死成单一类型。

## 阶段拆分

### P0：基础联调阶段

这一阶段的目标是让前端具备和后端“稳定说话”的能力，并把最基础的扫码登录
链路跑通。`P0` 没完成前，不建议多人并行开发后面的复杂页面。

#### P0-1 统一请求层

目标如下：

- 封装 `weRssRequest`
- 封装 `weRssTextRequest`
- 统一注入 `Authorization`
- 统一注入 `X-Tenant-ID`
- 统一处理 JSON / XML / HTML 三种读取方式

验收标准如下：

- 能正常请求 `GET /credentials/`
- 漏传 `X-Tenant-ID` 时能稳定识别为联调问题
- RSS / HTML 接口不会被错误按 JSON 解析

#### P0-2 通用任务轮询模块

目标如下：

- 统一封装任务轮询逻辑
- 支持 `pending / running / success / failed`
- 统一超时处理
- 统一失败提示

验收标准如下：

- 扫码登录、公众号同步、文章导入、文章刷新都能复用同一套轮询逻辑

#### P0-3 凭证与扫码登录页

目标如下：

- 展示凭证列表
- 创建扫码登录会话
- 展示二维码
- 轮询登录结果
- 设置默认凭证
- 检查凭证状态

验收标准如下：

- 能成功扫码并生成凭证
- 新凭证能出现在列表中
- 默认凭证可以切换
- 凭证状态检查结果可见

### P1：核心业务阶段

这一阶段的目标是跑通公众号和文章主链路。`P1` 完成后，这套前端就已经不再是
“能联调”，而是“能真实使用”。

#### P1-1 公众号搜索与订阅页

目标如下：

- 搜索微信平台公众号
- 从搜索结果直接订阅
- 支持查看当前 member 是否已订阅

依赖接口如下：

- `GET /feeds/search/?keyword=...`
- `POST /feeds/subscribe/`
- `GET /feeds/?subscribed_only=true`

验收标准如下：

- 有默认有效凭证时可以搜到公众号
- 可以将搜索结果订阅为当前 member 的 feed
- 订阅后列表中 `is_subscribed` 正确变化

#### P1-2 公众号管理页

目标如下：

- 展示当前 tenant 的 feed 列表
- 支持仅看已订阅 feed
- 编辑公众号信息
- 取消订阅
- 触发公众号同步

依赖接口如下：

- `GET /feeds/`
- `GET /feeds/?subscribed_only=true`
- `GET /feeds/{id}/`
- `PUT /feeds/{id}/`
- `DELETE /feeds/{id}/subscribe/`
- `POST /feeds/{id}/sync/`

验收标准如下：

- 列表正常展示
- 可以修改 `mp_name`、`mp_intro`、`credential_id`、`is_featured`
- 可以取消当前 member 的订阅
- 可以发起同步并看到任务结果

#### P1-3 文章导入口

目标如下：

- 支持输入微信文章 URL 导入单篇文章
- 导入成功后能跳转文章详情或文章列表高亮

依赖接口如下：

- `POST /articles/import-by-url/`
- `GET /tasks/{task_id}/`

验收标准如下：

- 输入合法微信文章 URL 后能生成导入任务
- 成功后能定位到导入结果文章

#### P1-4 文章列表页

目标如下：

- 展示文章列表
- 支持服务端标题搜索
- 支持按类型过滤
- 支持仅看收藏
- 切换收藏状态
- 单篇刷新
- 删除文章

依赖接口如下：

- `GET /articles/`
- `GET /articles/?search=...`
- `GET /articles/?article_type=...`
- `GET /articles/?favorite_only=true`
- `PUT /articles/{id}/favorite/`
- `POST /articles/{id}/refresh/`
- `DELETE /articles/{id}/`

验收标准如下：

- 同步后的文章能在列表中看到
- `search`、`article_type`、`favorite_only` 都可用
- 收藏状态可以正常切换
- 刷新成功后列表能看到最新字段

#### P1-5 文章详情页

目标如下：

- 展示标题、摘要、发布时间和正文
- 支持跳原文
- 支持从列表页进入详情

依赖接口如下：

- `GET /articles/{id}/`

可选增强接口如下：

- `GET /rss/content/{article_id}/`

验收标准如下：

- 能稳定展示正文 HTML
- 不依赖旧的“上一篇 / 下一篇”接口

### P2：体验与补强阶段

这一阶段不是主链路阻塞项，但能提升交付完整度。

#### P2-1 RSS / HTML 调试页

目标如下：

- 查看 tenant RSS XML
- 查看单 feed RSS XML
- 查看单篇正文 HTML

依赖接口如下：

- `GET /rss/`
- `GET /rss/{feed_id}/`
- `GET /rss/content/{article_id}/`

#### P2-2 统一异常态和空状态

目标如下：

- 统一 401 / 403 / 404 / 500 提示
- 统一任务失败提示
- 统一无凭证、无 feed、无文章时的空状态

## 当前不要纳入本期排期的能力

下面这些能力当前后端还没有提供，这期前端不要误以为已经可以做：

- 文章 `read` 接口
- 文章 `is_read` 字段
- 文章按 `feed_id` 的服务端过滤
- 文章未读过滤
- 上一篇 / 下一篇文章接口
- OPML 导出
- Atom / JSON / Markdown / Text 等多格式输出

前端 B 负责：

## 时间建议

如果前端基础设施已经具备，且接口环境稳定，可以按下面节奏预估：

| 阶段 | 建议时长 | 说明 |
| --- | --- | --- |
| `P0` | 1 到 2 天 | 请求层、扫码登录、任务轮询 |
| `P1` | 2 到 4 天 | 公众号与文章主链路 |
| `P2` | 1 到 2 天 | RSS 调试、异常态、空状态 |

## 最终验收口径

本期收口时，建议按下面顺序验收：

1. 请求层能自动带鉴权头和 tenant 头。
2. 扫码登录能生成凭证。
3. 默认凭证设置生效。
4. 公众号搜索、订阅、取消订阅、同步可用。
5. 同步后文章列表有数据。
6. 文章搜索、收藏、刷新、删除都可用。
7. 文章详情可正常阅读。
8. RSS XML 和正文 HTML 可以读取。
