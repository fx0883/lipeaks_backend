# we_rss 总览与对接说明

这份文档先讲清楚 `we_rss` 这套接口的基础约束，方便前端在接具体
接口之前先把认证、请求头、响应解析和错误处理一次性搭好。读完这份
文档后，你再看各模块 API 文档会更顺。

`we_rss` 是当前 Django 项目中的一个独立 app，数据和现有
`cms.Article` 完全分离，只负责“微信公众号 / 微信公众号文章 /
微信抓取凭证 / RSS”相关能力。

## 基础信息

这套 API 的基础前缀固定如下。

```text
/api/v1/we-rss/
```

本地开发时，完整基准地址通常类似这样。

```text
http://localhost:8000/api/v1/we-rss/
```

## 认证方式

所有 `we_rss` API 都要求使用当前项目的 `Member JWT`。这意味着前端
不能用管理员 token，也不能当匿名接口调用。

每个请求都要带下面两个请求头。

```http
Authorization: Bearer <member_access_token>
X-Tenant-ID: <current_member_tenant_id>
```

## X-Tenant-ID 规则

`we_rss` 的 tenant 隔离走的是项目现有 `common` 模块能力。前端如果
没有正确传 `X-Tenant-ID`，后端会直接拒绝请求。

`X-Tenant-ID` 的规则如下。

| 规则 | 说明 |
| --- | --- |
| 必填 | 所有 `we_rss` API 都必须传 |
| 必须匹配 | 值必须等于当前登录 `member.tenant.id` |
| 不能跨租户 | 如果 token 属于 tenant A，却传 tenant B，会被拒绝 |
| member 无 tenant 时拒绝 | 没有关联 tenant 的 member 不能访问 `we_rss` |

## 数据隔离模型

`we_rss` 的数据不是“某个 member 私有”，而是“某个 tenant 共享”。
这一点对前端展示逻辑很重要。

例如：

- A 成员在 tenant 1 下扫码登录成功后创建了微信凭证。
- B 成员也属于 tenant 1。
- B 成员调用凭证列表、公众号列表、文章列表时，能看到这份数据。

所以前端不应该把 `we_rss` 的数据理解成“我的凭证”“我的公众号”
“我的文章”，而应该理解成“当前租户共享的数据”。

## 标准成功响应格式

所有 JSON 类型接口都返回项目统一的响应包裹格式。

```json
{
  "success": true,
  "code": 2000,
  "message": "操作成功",
  "data": {}
}
```

字段含义如下。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `success` | `boolean` | 是否成功 |
| `code` | `number` | 业务状态码，成功通常是 `2000` |
| `message` | `string` | 给前端和用户看的结果说明 |
| `data` | `object \| array \| null` | 真实业务数据 |

## 标准错误响应

`we_rss` 当前复用项目通用错误响应定义。前端至少要处理下面几类情况。

| HTTP 状态码 | 含义 | 常见原因 |
| --- | --- | --- |
| `400` | 请求参数错误 | 缺必填字段、字段类型不对、URL 非法 |
| `401` | 未认证或 token 无效 | 没带 token、token 过期 |
| `403` | 无权限 | `X-Tenant-ID` 不匹配、member 无 tenant |
| `404` | 资源不存在 | `id` 对应的数据不在当前 tenant 内 |
| `500` | 服务端错误 | 微信抓取链路异常、未知服务错误 |

一个典型错误响应可以按下面理解。

```json
{
  "success": false,
  "code": 4003,
  "message": "没有权限执行该操作",
  "data": null
}
```

> **注意：** 某些微信抓取失败不会直接体现在 HTTP 失败上，而是体现在
> 同步任务本身的 `status = "failed"` 和 `result_payload.error` 中。

## 非 JSON 接口

`we_rss` 不全是 JSON 接口。前端需要根据接口类型选择不同的解析方式。

| 接口类型 | Content-Type | 前端解析方式 |
| --- | --- | --- |
| 普通业务接口 | `application/json` | `await response.json()` |
| RSS 聚合输出 | `application/xml` | `await response.text()` |
| 文章正文输出 | `text/html` | `await response.text()` |

## 任务驱动模型

微信相关操作里，最重要的特点是很多动作都不是“请求发出去马上拿结果”，
而是“先创建后台任务，再轮询任务结果”。

这几个能力都是异步任务。

| 任务类型 | 触发接口 | 作用 |
| --- | --- | --- |
| `credential_login` | 创建扫码登录会话后自动触发 | 后台轮询微信扫码登录状态 |
| `feed_sync` | 公众号同步接口 | 抓取公众号文章并 upsert 到 `WechatArticle` |
| `article_import` | 按 URL 导入文章接口 | 导入单篇微信文章 |
| `article_refresh` | 文章刷新接口 | 刷新正文和统计字段 |

## 推荐的前端请求封装

前端最好在 HTTP Client 层统一处理 token、租户头和响应包裹。

下面是一个推荐的 `fetch` 封装示例。

```ts
type ApiEnvelope<T> = {
  success: boolean;
  code: number;
  message: string;
  data: T;
};

async function weRssRequest<T>(
  path: string,
  options: RequestInit = {},
): Promise<ApiEnvelope<T>> {
  const token = localStorage.getItem("member_access_token");
  const tenantId = localStorage.getItem("member_tenant_id");

  const response = await fetch(`/api/v1/we-rss${path}`, {
    ...options,
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${token}`,
      "X-Tenant-ID": String(tenantId),
      ...(options.headers || {}),
    },
  });

  return response.json();
}
```

如果是 RSS 或正文输出接口，要改成读取文本。

```ts
async function weRssTextRequest(path: string): Promise<string> {
  const token = localStorage.getItem("member_access_token");
  const tenantId = localStorage.getItem("member_tenant_id");

  const response = await fetch(`/api/v1/we-rss${path}`, {
    headers: {
      Authorization: `Bearer ${token}`,
      "X-Tenant-ID": String(tenantId),
    },
  });

  return response.text();
}
```

## 完整调用链路示例

前端完整接一轮功能时，建议按下面链路实现页面和状态管理。

### 链路一：扫码登录并拿到微信凭证

这条链路适合“第一次接微信能力”。

1. 调用“创建扫码登录会话”接口。
2. 拿到 `session_id`、`qr_code_url`、`qr_code_image`。
3. 页面展示二维码。
4. 前端轮询“登录会话详情”接口。
5. 如果状态变成 `success`，拿到 `credential_id`。
6. 如果状态变成 `failed` 或 `expired`，提示用户重新扫码。

### 链路二：搜索公众号并同步文章

这条链路适合“管理公众号库”。

1. 先保证当前 tenant 有可用凭证，最好有默认凭证。
2. 调用“搜索公众号”接口。
3. 让用户选择某个公众号结果。
4. 调用“创建公众号”接口，保存到当前 tenant。
5. 调用“公众号同步”接口，拿到一个 `feed_sync` 任务。
6. 轮询任务详情，直到 `success` 或 `failed`。
7. 同步成功后刷新文章列表。

### 链路三：按 URL 导入单篇文章

这条链路适合“用户手工粘贴微信文章链接导入”。

1. 用户输入微信文章 URL。
2. 调用“按 URL 导入文章”接口。
3. 拿到 `article_import` 任务。
4. 轮询任务详情。
5. 成功后从 `result_payload.article_id` 拿到文章 ID 并跳详情页。

### 链路四：RSS 阅读和正文渲染

这条链路适合“前端内嵌阅读器”或“提供 RSS 订阅链接”。

1. 调用 tenant RSS 或单公众号 RSS 接口。
2. 用文本方式读取 XML。
3. 如果需要阅读正文，调用文章正文 HTML 接口。
4. 把返回的 HTML 渲染到前端容器中。

## 前端状态管理建议

这套 API 比较适合在前端按模块拆状态。

| 状态域 | 建议存什么 |
| --- | --- |
| `credential` | 凭证列表、默认凭证、登录会话 |
| `feed` | 公众号列表、搜索结果、当前公众号 |
| `article` | 文章列表、文章详情、已读和收藏状态 |
| `task` | 当前任务详情、轮询状态、最后错误 |
| `rss` | XML 文本、正文 HTML 文本 |
