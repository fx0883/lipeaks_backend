# RBAC系统架构设计

本文档描述面向双用户模型（管理员用户User和普通用户Member）的RBAC权限控制系统的整体架构设计。

## 1. 系统概述

### 1.1 设计目标

设计一个灵活、可扩展且高性能的RBAC权限控制系统，满足以下目标：

1. 支持双用户模型（User和Member）的统一权限管理
2. 实现细粒度的权限控制和租户隔离
3. 提供高性能的权限检查机制
4. 灵活适应业务需求变化
5. 便于集成与维护的架构设计

## 2. 系统组件设计

### 2.1 核心数据模型

RBAC系统的核心数据模型如下：

```
+----------------+        +----------------+        +----------------+
|   Permission   |        | RolePermission |        |     Role       |
+----------------+        +----------------+        +----------------+
| id             |<-------| permission_id  |        | id             |
| code           |        | role_id        |------->| name           |
| name           |        +----------------+        | code           |
| description    |                                  | description    |
| category       |                                  | tenant_id      |
| is_system      |                                  | is_system      |
+----------------+                                  +----------------+
                                                           ^
                                                           |
                                                   +----------------+
                                                   |    UserRole    |
                                                   +----------------+
                                                   | id             |
                                                   | user_type      |
                                                   | user_id        |
                                                   | role_id        |
                                                   | is_active      |
                                                   | start_date     |
                                                   | end_date       |
                                                   +----------------+
                                                           ^
                                                           |
                       +----------------------------------+----------------------------------+
                       |                                                                     |
               +----------------+                                                    +----------------+
               |      User      |                                                    |     Member     |
               +----------------+                                                    +----------------+
               | id             |                                                    | id             |
               | username       |                                                    | username       |
               | is_super_admin |                                                    | tenant_id      |
               | is_admin       |                                                    | ...            |
               | tenant_id      |                                                    +----------------+
               | ...            |
               +----------------+
```

#### 2.1.1 数据模型关系说明

- **Permission（权限）**：系统中的最小权限单元
- **Role（角色）**：权限的集合，是分配给用户的基本单位
- **RolePermission（角色权限关联）**：关联角色和权限的中间表
- **UserRole（用户角色关联）**：关联用户和角色的中间表，支持双用户类型
- **User（管理员用户）**：系统管理员用户模型
- **Member（普通用户）**：系统普通用户模型

### 2.2 权限检查架构

权限检查是RBAC系统的核心功能，其架构设计如下：

```
+------------------+     +------------------+     +------------------+
|    请求上下文    |---->|  权限检查入口    |---->|  用户类型判断   |
+------------------+     +------------------+     +------------------+
                                                          |
                                                          v
+------------------+     +------------------+     +------------------+
|  返回检查结果    |<----|  权限策略评估    |<----|  获取用户权限   |
+------------------+     +------------------+     +------------------+
                                 ^                        |
                                 |                        v
                         +------------------+    +------------------+
                         |  特殊规则处理    |    |  权限缓存查询    |
                         +------------------+    +------------------+
                                                          |
                                                          v
                                                 +------------------+
                                                 |  数据库权限查询  |
                                                 +------------------+
```

#### 2.2.1 权限检查流程说明

1. **请求上下文**：包含用户信息、请求资源、操作类型等
2. **权限检查入口**：统一的权限检查API
3. **用户类型判断**：区分User和Member不同用户类型
4. **获取用户权限**：从缓存或数据库获取用户的权限集合
5. **权限策略评估**：根据权限规则评估用户是否有权限
6. **特殊规则处理**：处理超级管理员、资源所有者等特殊规则
7. **返回检查结果**：返回权限检查的最终结果

### 2.3 缓存架构

为提高权限检查性能，设计了多级缓存架构：

```
+------------------+     +------------------+     +------------------+
|  权限检查请求    |---->|  本地内存缓存    |---->|  分布式缓存     |
+------------------+     +------------------+     +------------------+
        ^                        |                        |
        |                        v                        v
+------------------+     +------------------+    +------------------+
|  返回权限结果    |<----|  缓存命中处理    |    |  数据库查询     |
+------------------+     +------------------+    +------------------+
                                 ^                        |
                                 |                        v
                                 +--------------------+------------------+
                                                      |  更新缓存       |
                                                      +------------------+
```

#### 2.3.1 缓存策略

1. **本地内存缓存**：应用实例内的内存缓存，响应速度最快
2. **分布式缓存**：基于Redis的分布式缓存，保证集群间一致性
3. **缓存失效机制**：
   - 基于过期时间的自动失效
   - 基于权限变更的主动失效
   - 基于用户角色变更的主动失效

## 3. 多租户架构

RBAC系统支持多租户隔离，其架构设计如下：

### 3.1 租户隔离模型

```
+------------------+     +------------------+     +------------------+
|     租户A        |     |     租户B        |     |     租户C        |
+------------------+     +------------------+     +------------------+
|                  |     |                  |     |                  |
|  +------------+  |     |  +------------+  |     |  +------------+  |
|  |   用户     |  |     |  |   用户     |  |     |  |   用户     |  |
|  +------------+  |     |  +------------+  |     |  +------------+  |
|                  |     |                  |     |                  |
|  +------------+  |     |  +------------+  |     |  +------------+  |
|  |   角色     |  |     |  |   角色     |  |     |  |   角色     |  |
|  +------------+  |     |  +------------+  |     |  +------------+  |
|                  |     |                  |     |                  |
+------------------+     +------------------+     +------------------+
           |                      |                        |
           v                      v                        v
+----------------------------------------------------------+
|                     共享权限定义                           |
+----------------------------------------------------------+
|                                                          |
|  +---------------------+    +---------------------+      |
|  |   系统级权限        |    |   应用级权限        |      |
|  +---------------------+    +---------------------+      |
|                                                          |
+----------------------------------------------------------+
```

### 3.2 租户权限隔离策略

1. **数据级隔离**：每个租户的角色和用户角色关联都有租户标识
2. **权限检查隔离**：权限检查时自动包含租户过滤条件
3. **系统级与租户级角色区分**：
   - 系统级角色：跨租户共享，无租户ID
   - 租户级角色：特定租户专有，带有租户ID

## 10. 技术选择建议

为实现上述架构，推荐以下技术栈：

1. **框架**：Django + Django REST Framework
2. **数据库**：PostgreSQL（支持良好的事务和索引机制）
3. **缓存**：Redis（支持多级缓存和分布式锁）
4. **消息队列**：RabbitMQ（支持权限变更通知）
5. **监控**：Prometheus + Grafana（性能监控和告警）
6. **日志**：ELK Stack（日志收集和分析）
7. **部署**：Docker + Kubernetes（容器化部署和编排）
