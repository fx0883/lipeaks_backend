# 用户反馈系统需求分析

## 文档信息
- **版本**: v1.0
- **创建日期**: 2025-10-22
- **最后更新**: 2025-10-22

## 1. 需求背景

### 1.1 业务背景
- 系统中有多个软件产品（SoftwareProduct）
- 每个软件产品属于特定租户
- 用户购买许可证（License）后使用软件
- 需要收集用户对软件的反馈，以改进产品

### 1.2 用户角色
1. **超级管理员（SuperAdmin）**
   - 系统最高权限
   - 可查看本租户的所有反馈
   - **注意**: 不能跨租户查看

2. **租户管理员（TenantAdmin）**
   - 管理本租户的软件产品
   - 可查看本租户所有反馈
   - 可回复、处理反馈

3. **普通用户/会员（User/Member）**
   - 注册用户
   - 可能购买了许可证
   - 可提交反馈
   - 只能查看自己的反馈

4. **匿名用户（Anonymous）**
   - 未注册用户
   - 可提交反馈
   - 必须提供邮箱以接收回复
   - 无法查看反馈

### 1.3 业务痛点
- 缺乏统一的反馈收集渠道
- 反馈信息分散，难以管理
- 无法追踪反馈处理进度
- 用户无法及时获知反馈处理结果

## 2. 功能需求

### 2.1 反馈提交 ⭐⭐⭐⭐⭐

#### FR-001: 用户反馈提交
**描述**: 所有用户（包括匿名）都可以提交反馈

**输入**:
- 标题（必填，最多200字符）
- 详细描述（必填，最多5000字符）
- 反馈类型（必选）：Bug报告、功能请求、使用体验、性能问题、安全问题、其他
- 优先级（可选）：低、中、高、紧急
- 关联软件产品（必选）
- 软件版本（可选）
- 关联许可证（可选）
- 联系邮箱（匿名用户必填）
- 环境信息（自动收集，可选）
- 附件（可选，最多5个文件）

**处理逻辑**:
1. 验证必填字段
2. 如果是匿名用户，验证邮箱格式
3. 保存反馈到数据库
4. 设置初始状态为"已提交"
5. 如果是匿名用户且有邮箱，发送邮箱验证邮件
6. 返回反馈ID和提交成功信息

**输出**:
```json
{
  "success": true,
  "code": 2000,
  "message": "反馈提交成功",
  "data": {
    "feedback_id": 123,
    "tracking_number": "FB-20251022-001",
    "status": "submitted",
    "email_sent": true,
    "verification_required": true
  }
}
```

**验收标准**:
- ✅ 注册用户可成功提交反馈
- ✅ 匿名用户提供邮箱后可提交反馈
- ✅ 匿名用户未提供邮箱也能提交，但系统标记"无法回复"
- ✅ 环境信息自动收集（前端传入）
- ✅ 附件上传成功（支持图片、日志文件）

**筛选条件**:

- 提交日期范围
- 提交人
- 关键词搜索（标题、描述）

### 2.3 反馈回复 ⭐⭐⭐⭐⭐

#### FR-005: 添加回复
**描述**: 管理员对反馈进行回复，系统自动发送邮件

**权限**:
- 超级管理员：可回复本租户反馈
- 租户管理员：可回复本租户反馈
- 普通用户：不能回复
- 匿名用户：不能回复

**回复类型**:
1. **官方回复**: 发送邮件给用户
2. **内部备注**: 仅内部可见，不发送邮件

**输入**:
- 回复内容（必填，最多2000字符）
- 回复类型（必选：官方回复/内部备注）
- 是否同时变更状态（可选）

**处理逻辑**:
1. 验证权限
2. 保存回复到数据库
3. 如果是官方回复：
   - 获取收件人邮箱
   - 生成邮件内容
   - 触发异步邮件发送任务
   - 记录邮件日志
4. 更新反馈的最后回复时间
5. 如果需要，更新反馈状态

**邮件发送逻辑**:
```
判断回复类型
    ├─ 内部备注：不发送邮件
    └─ 官方回复：
        ├─ 获取收件人邮箱
        │   ├─ 注册用户：使用账号邮箱
        │   └─ 匿名用户：使用提交时的邮箱
        ├─ 如果无邮箱：标记"无法发送"
        └─ 如果有邮箱：
            ├─ 生成邮件内容（使用模板）
            ├─ 异步发送邮件
            ├─ 记录邮件日志
            └─ 更新发送状态
```

**邮件内容示例**:
```
主题: [软件名称] 您的反馈已收到回复

尊敬的用户，

您提交的反馈已收到我们的回复：

反馈编号：FB-20251022-001
反馈主题：软件启动时出现错误
提交时间：2025-10-22 10:30:00
当前状态：处理中

---
官方回复：
感谢您的反馈。我们已经定位到问题原因，是由于配置文件损坏导致的。
请尝试以下解决方案：
1. 删除配置文件 config.json
2. 重新启动软件
3. 重新进行初始化设置

如果问题仍未解决，请继续回复此邮件告知我们。
---

如需查看完整反馈详情，请访问：
https://yoursite.com/feedbacks/123

如不希望继续接收此类邮件，请点击退订：
https://yoursite.com/unsubscribe?token=xxx

此致
[租户名称] 技术支持团队
```

### 2.4 状态管理 ⭐⭐⭐⭐

#### FR-007: 变更反馈状态
**描述**: 管理员可以变更反馈状态

**状态流转**:
```
已提交(submitted)
    ↓
审阅中(reviewing)
    ↓
已确认(confirmed)
    ↓
处理中(in_progress)
    ↓
已解决(resolved)
    ↓
已关闭(closed)

特殊状态（可从任意状态跳转）:
- 已拒绝(rejected)
- 重复(duplicate)
```

**权限**:
- 超级管理员：可变更本租户反馈状态
- 租户管理员：可变更本租户反馈状态
- 普通用户：不能变更
- 匿名用户：不能变更

**输入**:
- 新状态（必选）
- 变更原因（可选，建议填写）
- 是否发送邮件通知（可选，默认true）

**处理逻辑**:
1. 验证权限
2. 验证状态流转是否合法
3. 更新反馈状态
4. 记录状态变更历史
5. 如果开启邮件通知，发送状态变更邮件

**邮件通知**:
```
主题: [软件名称] 您的反馈状态已更新

尊敬的用户，

您的反馈状态已更新：

反馈编号：FB-20251022-001
反馈主题：软件启动时出现错误
原状态：处理中
新状态：已解决

变更说明：
问题已在v1.2.4版本中修复，请更新到最新版本。

---

如需查看详情，请访问：
https://yoursite.com/feedbacks/123
```

---

#### FR-008: 查看状态历史
**描述**: 查看反馈的所有状态变更记录

**显示内容**:
- 变更时间
- 原状态 → 新状态
- 操作人
- 变更原因

### 2.5 投票功能 ⭐⭐⭐

#### FR-009: 反馈投票
**描述**: 注册用户可以对反馈进行投票，表示关注或支持

**权限**:
- 注册用户（User/Member）：可投票
- 匿名用户：不能投票

**规则**:
- 每个用户对同一反馈只能投票一次
- 可以取消投票

**处理逻辑**:
1. 验证用户是否已投票
2. 如果未投票，创建投票记录
3. 更新反馈的投票计数

**用途**:
- 识别热门需求
- 辅助优先级判断
- 用户参与感

### 2.6 附件管理 ⭐⭐⭐

#### FR-010: 上传附件
**描述**: 用户提交反馈时可以上传附件

**限制**:
- 文件大小：单个文件不超过10MB
- 文件类型：图片（jpg, png, gif）、日志文件（txt, log）、压缩包（zip）
- 数量限制：每个反馈最多5个附件

**处理逻辑**:
1. 验证文件类型和大小
2. 生成唯一文件名
3. 保存到MEDIA目录
4. 记录附件信息到数据库

**安全考虑**:
- 重命名文件，防止恶意文件名
- 扫描文件类型，防止伪装
- 存储路径隔离，按租户分目录

### 2.7 统计分析 ⭐⭐⭐

#### FR-011: 反馈统计
**描述**: 提供反馈数据的统计分析

**统计维度**:
1. **按类型统计**: 各类型反馈数量
2. **按状态统计**: 各状态反馈数量

7. **热门反馈**: 投票数最多的TOP 10

**权限**:
- 管理员：可查看本租户统计数据
- 普通用户：不能查看

## 4. 业务规则

### 4.1 邮箱规则
1. **注册用户**: 自动使用账号邮箱
2. **匿名用户**: 必须提供邮箱才能接收回复
3. **邮箱验证**: 匿名用户需验证邮箱（24小时内）
4. **退订机制**: 用户可选择不接收邮件通知

### 4.2 反馈关闭规则
1. 状态为"已解决"后14天未有新回复，自动变更为"已关闭"
2. 状态为"已拒绝"或"重复"后立即变更为"已关闭"
3. 已关闭的反馈不能再回复，但可重新打开

### 4.3 垃圾反馈防护
1. 同一邮箱/IP每小时最多提交3个反馈
2. 匿名用户未验证邮箱的反馈，7天后自动删除
3. 标题或描述包含敏感词，需人工审核

### 4.4 附件清理规则
1. 反馈删除后，附件保留30天后自动清理
2. 未验证邮箱的匿名反馈，附件7天后清理
