## 修复内容

### 1. cms/permissions.py 修复

#### 修复点1: 安全访问用户属性
```python
# 修复前
if user.is_super_admin:
if user.is_admin:

# 修复后
if getattr(user, 'is_super_admin', False):
if getattr(user, 'is_admin', False):
```

**说明**: Member对象没有`is_super_admin`和`is_admin`属性，使用`getattr`安全访问

#### 修复点2: 作者身份检查支持GenericForeignKey
```python
# 修复前
obj_author_id = None
if hasattr(obj, 'author_id'):
    obj_author_id = obj.author_id
elif hasattr(obj, 'author'):
    obj_author_id = obj.author.id if obj.author else None
# ...
if obj_author_id == user.id:
    return True

# 修复后
obj_author = None
if hasattr(obj, 'author'):
    obj_author = obj.author
elif hasattr(obj, 'user'):
    obj_author = obj.user

# 检查是否是自己的资源（直接比较对象，支持不同用户类型）
if obj_author and obj_author == user:
    return True
```

**说明**: 
- 直接比较作者对象而不是ID
- 支持不同用户类型（User和Member）的比较
- GenericForeignKey的author可以是User或Member实例

### 2. cms/member_article_views.py 修复

#### 修复点: 发布文章序列化器使用
```python
# 修复前
serializer = ArticleDetailSerializer(article, context={'request': request})
return Response(serializer.data)

# 修复后
serializer = self.get_serializer(article)
return Response(serializer.data, status=status.HTTP_200_OK)
```

**说明**: 
- 使用`self.get_serializer()`获取正确配置的序列化器
- 明确指定HTTP状态码

## 技术细节

### GenericForeignKey对象比较

Python的对象相等性比较（`==`）会自动处理不同类型：

```python
# User对象
user = User.objects.get(id=1)

# Member对象  
member = Member.objects.get(id=1)

# Article的author可以是User或Member
article.author == user      # True if author是这个User
article.author == member    # True if author是这个Member

# 即使是不同的模型类，Django的pk比较也能正确工作
```

### 权限检查流程

1. **has_permission**: 检查用户是否有基本权限
2. **has_object_permission**: 检查用户是否可以操作特定对象
3. **作者检查**: 直接比较`obj.author == user`
4. **租户检查**: 验证对象租户与用户租户一致
