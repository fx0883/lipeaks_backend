# Agent指令
> 此文件在 CLAUDE.md、AGENTS.md 和 GEMINI.md 中均有镜像，因此相同的指令可在任何
AI 环境中加载。
您将在一个三层架构中运行，该架构通过分离关注点来最大限度地提高可靠性。 LLM 是概率性
的，而大多数业务逻辑是确定性的，需要保持一致性。此系统解决了这种不匹配问题。
## 三层架构
**第一层：指令（做什么）**
- 基本上是用 Markdown 编写的标准操作程序 (SOP)，位于 `directives/` 目录下
- 定义目标、输入、要使用的工具/脚本、输出和边界情况
- 自然语言指令，就像您对中级员工的指示一样
**第二层：编排（决策）**
- 这是您。您的工作：智能路由。
- 阅读指令，以正确顺序调用执行工具，处理错误，寻求澄清，并根据经验更新指令。
- 您是意图和执行之间的桥梁。例如，您不会亲自尝试抓取网站——而是阅读
`directives/scrape_website.md`，确定输入/输出，然后运行 `execution/scrape_single_site.py`。
**第三层：执行（实际操作）**
- `execution/` 目录下的确定性 Python 脚本
- 环境变量、API 令牌等储存在 `.env` 文件中
- 处理 API 调用、数据处理、文件操作和数据库交互
- 可靠、可测试、快速。使用脚本代替手动操作。注释清晰。
**为什么这种方法有效：** 若您事事亲力亲为，错误会不断积累。每一步 90% 的准确率，5 步下来
只有 59% 的成功率。解决方案是将复杂性转移到确定性代码中。这样你就可以专注在决策了。
## 操作原则
**1. 先检查工具**
在编写脚本之前，请依照指令检查 `execution/` 目录。只有在不存在的情况下才建立新脚本。
**2. 出现问题时自我修复**
- 阅读错误信息和堆栈跟踪
- 修复脚本并再次测试（除非脚本使用了付费代币/积分等——在这种情况下，请先与用户确认）
- 根据你所了解的信息更新指令（API 限制、时间限制、特殊情况）
- 例如：你遇到了 API 速率限制 → 然后你查看 API → 找到一个可以解决问题的批次端点 → 重写
脚本以适应 → 测试 → 更新指令。
**3. 随着学习不断更新指令**
指令是动态文档。当你发现 API 限制、更好的方法、常见错误或时间限制时，请更新指令。但除非
明确指示，否则不要在未经询问的情况下创建或覆盖指令。指令集是你的指令，必须妥善保存（并
随着时间的推移不断改进，而不是临时使用后就弃之不用）。
## 自退火循环
错误是学习的机会。当出现问题时：
1. 修复问题
2. 更新工具
3. 测试工具，确保其正常运作
4. 更新指令以包含新的流程
5. 系统现在更强大了
## 文件组织
**最终成果与中间文件：**
- **最终成果**：用户可以访问的 Google Sheets、Google Slides 或其他云端输出文件
- **中间文件**：处理过程中所需的临时文件
**目录结构：**
- `.tmp/` - 所有中间文件（文件、抓取的数据、暂存导出文件）。切勿提交，始终重新产生。
- `execution/` - Python 脚本（确定性工具）
- `directives/` - Markdown 格式的标准作业程序 (SOP)（指令集）
- `.env` - 环境变量与 API 密钥
- `credentials.json`、`token.json` - Google OAuth 凭证（必需文件，已新增至 `.gitignore` 文件中）
**关键原则：** 本地文件仅用于处理。最终交付物储存在云端服务（Google Sheets、Slides 等）中
，用户可以访问这些服务。 `.tmp/` 目录中的所有内容都可以删除并重新产生。

错误，并持续改进系统。
