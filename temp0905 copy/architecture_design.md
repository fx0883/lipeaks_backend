# 机器绑定注册码系统架构设计

## 1. 设计目标与原则

### 1.1 核心目标
- 为macOS软件提供安全可靠的机器绑定注册码验证
- 与现有多租户系统无缝集成
- 支持灵活的许可证管理和分发
- 防止注册码被非法复制和滥用

### 1.2 设计原则
- **安全第一**: 多层加密和验证机制
- **兼容性**: 充分利用现有架构优势
- **可扩展性**: 支持未来功能扩展
- **用户友好**: 简化管理流程，提升用户体验

### 2.2 核心组件说明

#### A. macOS客户端组件
- **机器信息收集模块**: 收集硬件和系统唯一标识
- **注册码验证模块**: 处理注册码的验证和激活
- **离线验证缓存**: 支持短期离线使用

#### B. Django后端组件  
- **licenses应用**: 新增的许可证管理模块
- **验证服务**: 处理客户端验证请求
- **管理界面**: 基于现有权限系统的许可证管理

#### C. 数据存储
- **许可证数据**: 注册码、绑定信息、使用记录
- **审计日志**: 所有操作的完整记录
- **配置数据**: 软件产品和许可方案配置

## 4. 数据流设计

### 4.1 许可证生成流程
```
管理员操作 → 选择产品方案 → 生成注册码 → 分发给客户
     ↓
数据库记录 → 许可证状态:未激活 → 等待客户激活
```

### 4.2 软件激活流程  
```
客户端启动 → 输入注册码 → 收集机器信息 → 发送激活请求
     ↓
后端验证 → 检查注册码 → 生成机器绑定 → 返回激活证书
     ↓
客户端接收 → 保存激活信息 → 定期在线验证 → 正常使用
```

### 4.3 在线验证流程
```
客户端定时 → 发送心跳请求 → 携带机器指纹 → 验证激活状态
     ↓
后端处理 → 验证绑定关系 → 更新使用记录 → 返回验证结果
     ↓
客户端更新 → 刷新本地状态 → 继续正常使用
```
